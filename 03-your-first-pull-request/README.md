# How do I make my first pull request?

You copy the project, make your change on a separate branch, and then ask for that change to be pulled into the main version. On GitHub you can do the whole thing in your browser in about an hour, and you don't need a terminal.

**Level:** Beginner · **Type:** Tutorial (Build) · **Time:** about 1 hour · **Last checked:** 2026-11

> **TL;DR** A pull request (PR) is a proposal to change a project. It holds the change, the reason for it and the review in one place. In this guide you'll fork the hub, add a gift card answer to the Polish & Co. FAQ, open a PR, read your own diff and merge it.

> [!TIP]
> **New to this? Explain it like I'm new.**
> Think of suggesting edits in a shared Google Doc.
> - A **fork** is making your own copy of the doc so you can mark it up.
> - A **branch** is a draft version of that copy. The clean version stays untouched while you work.
> - A **commit** is a saved change with a short note saying what you changed.
> - A **pull request** is suggesting mode plus the comment thread. Someone can see exactly what you changed, ask questions and accept it.
> - **Merging** is accepting the suggestion. Now it's part of the clean version.
>
> That's the whole idea. The rest of this guide is the real thing on GitHub.

**You'll need:**
- A free GitHub account ([GitHub Docs: Creating an account on GitHub](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github))
- A web browser
- The [running example](../example/README.md), the Polish & Co. booking assistant. Give it a quick read first.

**What you'll learn:**
- What a fork, a branch, a commit and a pull request are, and how they fit together
- How to write a PR title and description someone can understand without asking you
- How to read a diff, then merge your change and tidy up
